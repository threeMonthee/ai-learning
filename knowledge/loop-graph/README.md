# Loop 与 Graph

这篇笔记回答一个问题：2026 年 X 上说的「不要再写 prompt，去写 loop，再写成 graph」，落到工程上到底是什么，以及在企业内部做一个版本需求时怎么用它做实验。

## 先看哪几篇

1. [来源与边界](01-来源与边界.md)：这次咨询里哪些是原话，哪些是剪辑号加进去的。
2. [工作机制](02-工作机制.md)：一次运行里谁触发、谁做事、谁判定停下、状态放在哪。
3. [企业内实验教程](03-企业内实验教程.md)：用一个真实需求把这套控制流跑起来的步骤。
4. [reference](reference/)：上面那套控制流的可运行实现。`npm test` 走通「可验证需求会自动重试一次再等人批」和「不可验证需求不会进入写代码」。

## 一句话

人写的是目标、努力上限和验证方法。循环负责反复把工作交给模型和工具，直到验证通过、预算用尽或需要人看。图负责把「下一步走哪条边」写成可以检查的条件，并在边上放确定性闸门和人。
